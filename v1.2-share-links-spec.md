# v1.2 Spec — Share Cards + Public Garage Links

**Goal:** Every build in TorqueDen becomes shareable outside the app — as a branded image card (for IG stories/posts) or a public web link (for bios, WhatsApp, Discord). The link's preview image *is* the card, so one generator powers both. Every share is an ad for TorqueDen.

**Why this works for us:** zero video/storage cost, reuses guest-mode's public-read RLS, and turns users' Instagram bios into a funnel ("garage link in bio" replaces "DM for spec list").

---

## 1. UX flows

### Share sheet (in-app)
A `Share` button on: car detail screen, post viewer, garage screen (own garage only for garage links).

Tapping opens a bottom sheet with two options:

1. **Share as image** — renders the branded card (see §3), opens the native share sheet with the PNG. Instagram Stories, WhatsApp, save to camera roll, wherever.
2. **Copy link / Share link** — generates/copies `https://torqueden.app/c/{slug}`. Native share sheet with the URL.

Both paths silently upload the freshly rendered card PNG to storage first (see §3.3) so the link preview always matches the current state of the build.

### Public web page (out-of-app)
`torqueden.app/c/{slug}` renders a read-only build page for non-users:

- Hero: car photo, nickname, make/model/year, chassis code, follower count
- Spec sheet (from `car_specs`)
- Build log grouped by category (from `build_entries`, photos included)
- Sticky footer CTA: **"Get TorqueDen — free on the App Store"** → App Store link
- OG meta tags: `og:image` points at the stored share card → pasting the link anywhere renders the branded card as preview

`torqueden.app/g/{username}` (phase 2): the whole garage — grid of the user's cars, each linking to its `/c/` page. This is the bio link.

### Owner controls
- Toggle per car: **"Public share link"** (default ON) in car edit screen. OFF → web page returns 404, link sharing hidden in share sheet. Image sharing always available (it's just a local render).

## 2. Data model (migration `0036_public_share.sql`)

```sql
-- Public share slugs + opt-out.
alter table public.cars
  add column if not exists public_slug   text unique,
  add column if not exists share_enabled boolean not null default true,
  add column if not exists link_visits   integer not null default 0;

create index if not exists idx_cars_public_slug on public.cars (public_slug);

-- Slug generation: nickname or make-model, lowercased, hyphenated,
-- + 4-char suffix for uniqueness. e.g. "hectors-civic-k4f2".
-- Generated in-app on first share (not a trigger — only cars that get
-- shared need slugs).

-- Anonymous visit counter, callable from the web page without auth.
create or replace function public.record_link_visit(slug text)
returns void
language sql
security definer
set search_path = public
as $$
  update public.cars
     set link_visits = link_visits + 1
   where public_slug = slug and share_enabled;
$$;

grant execute on function public.record_link_visit(text) to anon;
```

**RLS note:** guest mode already grants anon `select` on `cars`, `build_entries`, `car_specs` — the web page uses the same anon key and inherits the same policies. Verify the existing public-read policies don't filter out what the page needs; no new read policies expected.

**Privacy check:** the web page must never render `latitude`/`longitude` (fuzzed or not) or `location_name` beyond what the app already shows publicly. Select only the columns the page needs — never `select *`.

## 3. Share card generator (Flutter, client-side)

### 3.1 Design
One reusable widget `ShareCardView` rendered off-screen at fixed size **1080×1920** (stories) with a **1080×1350** variant (feed/4:5), matching existing brand treatment (`TorqueDen-brand-and-theme.md`, same look as the App Store caption bars):

- Car photo top (cover-cropped, ~60% of height)
- Carbon-weave dark background below, ember-orange accent bar at bottom
- Nickname + make/model/year + chassis code
- 3–5 headline mods pulled from most recent `build_entries` (or spec highlights)
- Follower count + reaction count if > 0 (social proof, hide when zero)
- `Torque`(white)`Den`(ember) wordmark + **QR code** pointing at the share link
- QR via `qr_flutter` package

### 3.2 Render pipeline
`RepaintBoundary` + `dart:ui toImage()` at 3× pixel ratio → PNG bytes. No server render, no cost. New service: `lib/services/share_service.dart`.

New packages: `share_plus` (native share sheet), `qr_flutter` (QR). Both pure-Dart/light, no platform config beyond iOS photo-permission string if saving to camera roll.

### 3.3 Card upload (for link previews)
On any share action: upload PNG to a **public** storage bucket `share-cards` at path `{car_id}.png` (upsert — one live card per car, no accumulation). Web page's `og:image` → the bucket's public URL. Cards are ~200–400 KB; at even 1,000 cars that's <400 MB — negligible.

## 4. Web layer (Supabase Edge Function `share-page`)

No new hosting. One edge function serves SSR HTML:

```
GET https://<project>.functions.supabase.co/share-page/c/{slug}
```

Routed from `torqueden.app/c/{slug}` however the marketing site is hosted (Cloudflare route/worker proxy, or a `share.torqueden.app` subdomain CNAME if simpler — decide at implementation, the function doesn't care).

Function behaviour:
1. Fetch car + specs + build entries via anon-scoped query on `public_slug`, `share_enabled = true`
2. 404 page (branded, with App Store CTA — even dead links convert) when missing/disabled
3. Render static HTML — inline CSS, dark theme, no JS framework. Fire `record_link_visit(slug)` non-blocking
4. OG/Twitter meta: title `"Hector's Civic — TorqueDen"`, description from car description or top mods, `og:image` = share card URL
5. `Cache-Control: public, max-age=300` — CDN-friendly, near-zero function invocations under load

**Smart-banner/deep-link (phase 2):** `apple-app-site-association` + `assetlinks.json` + `app_links` package so installed users open links in-app. Not needed for launch.

## 6. Phases

**Phase 1 (ship first):** migration, card generator, share sheet on car detail + post viewer, edge function `/c/` pages, visit counter.
**Phase 2:** `/g/{username}` garage pages, garage share button, deep links into app, link views stat.
**Phase 3 (only if wanted):** per-post share pages, meet share pages (`/m/{id}` — meets are inherently shareable: "who's going" + map).

## 7. Edge cases

- Car with no photo → card uses carbon-weave background + big wordmark; still looks intentional
- Deleted car → storage card orphan: delete `share-cards/{car_id}.png` in existing account/car deletion flow (`0023_delete_account_storage.sql` pattern)
- Slug collisions → retry with new suffix (unique constraint is the guard)
- Renamed nickname → slug is immutable once created (links never break); card re-renders with new name on next share
- Blocked users viewing web page: not preventable (public is public) — this is the same exposure as guest mode, no new surface
